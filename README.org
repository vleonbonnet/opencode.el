#+TITLE: opencode.el
#+OPTIONS: toc:nil

An Emacs client for [[https://opencode.ai/][OpenCode]] 2, the open source coding agent. Each session is a Comint buffer with Markdown rendering, collapsible reasoning and tool blocks, and permission requests and questions that wait for you without taking focus. It connects to the shared background service the OpenCode TUI and desktop app use, starting it when needed, and never stops it.

This package started as [[https://codeberg.org/sczi/opencode.el][sczi's opencode.el]] for OpenCode 1. It was rewritten for OpenCode 2's API and event model, keeping its Comint foundation and its post-edit hooks.

* Requirements

- Emacs 31.1 with the =markdown= and =markdown-inline= tree-sitter grammars (=M-x markdown-ts-mode-install-parsers=, or set =opencode-ensure-grammar-function=).
- [[https://github.com/magit/transient][transient]].
- OpenCode 2. The prompt-cache guard, stale-thinking consent and prompt-cache expiries need routes only [[https://github.com/vleonbonnet/opencode][my fork]] has; with stock OpenCode the guard switches itself off and no expiry is known.

* Installation

With elpaca or straight:

#+begin_src emacs-lisp
(use-package opencode
  :ensure (:host github :repo "vleonbonnet/opencode.el"))
#+end_src

With =package-vc=:

#+begin_src emacs-lisp
(use-package opencode
  :vc (:url "https://github.com/vleonbonnet/opencode.el" :rev :newest))
#+end_src

* The service

OpenCode 2 runs one background service per user. It registers its URL, process ID, version and password in =~/.local/state/opencode/service.json= (=$XDG_STATE_HOME/opencode/service.json= when set). Emacs reads that file, checks that the registered process answers, and runs =opencode service start= when none does: whatever stopped the service, a crash, a restart or a stop, the next request starts it again, a sent prompt included. A restarted service is found again from the file, and running turns resume. =M-x opencode-service-restart= restarts it, for instance after installing a new build; requests made meanwhile wait for the restarted service. =opencode-service-stale-functions= run when the service is older than the installed CLI. =M-x opencode-service-stop= stops it and closes Emacs's event stream, so that nothing starts it again by itself; a request starts it again, and the stream then reopens if session buffers are open or the session registry has clients.

The event stream reopens by itself when it drops, after a backoff, and at once when a service is ready again after Emacs started, restarted or found it again, or when a prompt is sent while it is closed, so that replies render. Only =M-x opencode-disconnect= keeps it closed, until something connects it again, such as opening a session. A stream that sends nothing, not even the heartbeat the service sends every 15 seconds, for =opencode-events-heartbeat-timeout= seconds is dropped and reopened; after the machine slept, or Emacs was busy, the silence counts from when Emacs could read the stream again, so a sleep costs no reconnection.

Nothing that happened while the stream was down is sent again, so every open session buffer then catches up with the service: it asks for its newest messages until the last one it showed complete, and writes only those after it, such as a turn that ran meanwhile; a buffer that missed nothing writes nothing. The buffers shown in a window go first, =opencode-resync-requests= at a time, and the events arriving meanwhile wait until the buffer has caught up. A buffer whose last message is gone, as after a revert, renders its whole transcript again. A transcript is written =opencode-replay-slice= seconds at a time, so that a long one never holds Emacs.

On its first start, the service imports the sessions of OpenCode 1 in the background while it already answers, and a session it has yet to import looks deleted. Emacs therefore waits for the import before sending anything, showing its progress in the echo area; an import that fails, or makes no progress for =opencode-service-import-stall-timeout= seconds, is reported as a warning and no longer waited for.

* Sessions

=M-x opencode= offers the sessions of the current project, including those of its worktrees, newest first, after an entry starting a new session there; in a project without sessions, it starts one at once. Subagent and archived sessions are left out. =opencode-select-project= first picks a project the service knows, most recently active first, then does the same there. =opencode-select-session= is another name for =opencode=.

opencode.el has no session list of its own: [[https://github.com/vleonbonnet/drover][drover]] lists the sessions of every project, for every agent front end it supports, from the session registry (see [[*Session state][Session state]]), which holds every unarchived session. =opencode-fetch-sessions= fetches sessions from the service by project, directory or parent, such as archived ones, for such lists.

Every session picker shows a session's status icon before its title, then the archive's icon for an archived session, and its project, its branch when known and the time since it last changed after it, such as =5m= or =2d=. The title takes the face of where the session is in Emacs: =opencode-session-active= in the window you work in, =opencode-session-shown= in another window, =opencode-session-open= in a buffer no window shows. Branches are read from each worktree's HEAD. A title given twice gets =<2>=, =<3>= and so on, so every session can be picked. The icons name the status in their tooltip, and are those of every display of sessions (see [[*Look][Look]]). The pickers are =opencode=, =opencode-select-project=, =opencode-select-open-session= (a session open in a buffer), =opencode-select-idle= (one that finished or started waiting while not displayed), =opencode-select-child-session= (a subagent of this session), and those of the commands below. The icon goes in the completion's prefix and the rest in its annotation, which completion UIs show without matching the input against them.

=opencode-rename-session=, =opencode-archive-session=, =opencode-delete-session= and =opencode-interrupt= act on the buffer's session in a session buffer. Elsewhere, they pick one of the current project's sessions, those =opencode= offers; =opencode-interrupt= offers only those running a turn.

Other entry points: =opencode-new-session=, =opencode-new-worktree= (a new branch in a worktree under =opencode-worktree-directory=, with a session in it), =opencode-consult-sessions=, =opencode-toggle-mcp= (connect or disconnect an MCP server), and =opencode-visit-last-idle= for the session that last finished or started waiting while not displayed.

opencode.el binds only the keys every Comint or special-mode user expects, and leaves its other commands unbound. drover provides key maps for them: one-key session actions in its session lists, and a transient (=drover-dispatch=) holding those, the prompt's commands and global ones. Without drover, call the commands with =M-x= or bind them yourself.

Messages that tell which command to run, such as "OpenCode question pending; C-' A answers it", name its keys through =opencode-command-keys=. That asks =opencode-command-keys-function= first: a function of a command, called in the buffer the hint is about, returning the keys that run it as a string in =key-description= form, or nil. drover sets it to name the keys of its maps. When it is nil or returns nil, the keys come from the current keymaps as =substitute-command-keys= finds them, or the hint reads =M-x= and the command's name.

* Session state

Emacs keeps the live state of every unarchived session and of every session open in a buffer, archived or not, in the registry =opencode-state=: whether a turn runs, the retry it waits for, the permission requests and questions waiting on you, and how the last turn ended. It follows the service's events, and rebuilds itself from the service every time the event stream connects, whoever opened it; =opencode-state-ensure= opens the stream for it. A rebuild first loads the newest page of sessions and the running ones, after which the registry is ready (=opencode-state-ready-p=) and follows events; it then lists the older sessions in the background, a page at a time, without holding Emacs up, until =opencode-state-loaded-p= says it holds them all. Until then, a rebuild after a reconnection keeps the entries it had. A session buffer opening fetches its session when the registry lacks it. =opencode-state-recent-limit=, nil by default, caps how many unarchived sessions it lists, the newest first.

A session's status, from =opencode-state-status=, is =waiting= while a request awaits you, =retrying= or =working= while a turn runs, =failed= or =done= when a turn ended that nobody viewed yet, and =idle= otherwise. =opencode-state-change-functions= run when a status changes and =opencode-state-updated-functions= when anything about a session does, for session lists, dashboards and mode lines of other packages; when many sessions change at once, as when a page of the listing arrives, the latter runs once with nil rather than once per session. =opencode-state-sessions= returns the unarchived entries and those of open buffers, newest first, and =opencode-state-subagent-statuses= which of =waiting=, =working= and =retrying= a session's subagents are in, at any depth. The session pickers show a session's title, project and status as the registry knows them when it holds the session, and otherwise as the session's last fetched info has them.

The registry also knows each session's context size, the tokens its next request sends again, as its buffer's mode line counts them: =opencode-state-context= returns it, nil when no step reported usage yet. The end of every step updates it. A compaction replaces the conversation, and only the next step measures what it left: until then the size is the service's estimate of the next request, which =opencode-state-context-estimated-p= (the entry's =:context-estimated=) tells, or nil from a service that gives none, as for a native compaction, where OpenCode's own clients show none either. The service lists sessions without it, so a session the registry loaded rather than saw created has it fetched, from its newest assistant message reporting usage and its newest completed compaction, the first time a client asks, at most =opencode-state-context-requests= sessions at a time; =opencode-state-updated-functions= run once it arrives. A reconnection keeps the sizes of the sessions the service has not updated since, except those of sessions seen compacting, which the service does not mark updated when the compaction ends. Only the sessions the registry holds have one.

Other packages show a session's agent, model, provider, variant and context use as the mode line does, for any session, with or without a buffer, from its agent and model reference (=:agent= and =:model= in the registry) and context size: =opencode-agent-display= (the catalog's name for the agent, bold, in the =color= the agent configures, else in one of =opencode-agent-faces= by its place among the primary agents), =opencode-model-display= (the compact name, such as =Opus 5.5= for Claude Opus 5.5; =opencode-model-name= gives the full one), =opencode-provider-display= (the icon from =opencode-provider-icons=, named in its tooltip), =opencode-variant-display= (the selected variant in =opencode-setting-chosen=, else the default one in =opencode-setting-inherited=) and =opencode-context-display= (a filling pie and the percentage of the model's context, in =opencode-context-near= near a long-context price tier and =opencode-context-over= past it, with a =~= before the percentage when given an estimate; its tooltip is =opencode-context-description=). =opencode-context-usage= gives the numbers behind it, for a gauge of one's own: =:tokens=, =:limit=, =:fraction= and =:tier=. Each takes the directory whose catalogs to read, such as the entry's =:directory=; none waits: a value needing a catalog not fetched yet is nil, the fetch starts, at most =opencode-catalog-requests= at a time, and =opencode-catalog-changed-functions= run when it arrives. When the event stream reconnects, the catalogs are kept and shown as they were; the first display asking for one again has it fetched anew, and the hook runs only for one that arrives different, as it does for one an event says changed. =opencode-catalog-location-generation= counts the changes of one location's catalogs, for caches of values derived from them.

A session may live in a directory deleted since, such as a scratch worktree, whose catalogs the service refuses. Its displays then show identifiers, the model's ID for its name, as for a model the catalog lacks; =opencode-location-missing-p= says so. The absence is logged once in =*Messages*=, without reaching the echo area, the hook runs once so that lists redraw, and no display asks for that location's catalogs again before the stream reconnects, when they are asked for once more.

With my fork, the registry also knows when each session's prompt cache runs out. =opencode-state-cache= returns the provider's cache entry that the session's next turn would reuse, as a plist: =:expires=, when it runs out, in float seconds since the epoch; =:ttl=, its retention window in seconds, which every response reusing it starts over; =:tokens=, the prompt tokens it covers; and =:prompt-tokens=, the whole prompt of the session's last request (uncached input, cache reads and writes), of which =:tokens= is the share cached, nil from a build of the fork that does not tell it. =opencode-state-cache-remaining= gives the seconds left. The expiries are listed whenever the event stream connects and follow each provider response; nothing reports an entry running out, so callers count down themselves, and the registry lists them again once the earliest known one passes, as a longer-lived entry, such as a system prompt cached for an hour, may outlive the conversation's. =opencode-state-updated-functions= run for every session whose expiry changed, whether or not the registry holds it. With stock OpenCode, =opencode-state-cache-supported-p= returns nil and no expiry is known.

Whether a finished turn was seen is the service's read marker, shared by every client. Showing a session's buffer in the selected window of a focused frame, or a turn ending while it is shown there, marks the session viewed (=opencode-session-view=), for the TUI and the desktop app too; a session viewed in another client is no longer done in Emacs either.

Archiving a session (=opencode-session-archive=) hides it from the pickers and from =opencode-state-sessions= without deleting it; =opencode-session-archive= with a non-nil RESTORE argument brings it back. Its optional THEN and ELSE tell the outcome: THEN gets the session's info once the service archived or restored it, the registry and the session's buffer knowing of it by then, ELSE the error of a refusal, which is otherwise reported; drover closes an archived session's buffer only from THEN. =opencode-session-archived-p= tells whether a session is archived, from the registry, else from its buffer, without asking the service.

Sending to an archived session brings it back first: a prompt, a slash command or a shell command sent from its buffer, queued input included, and a prompt or command sent with =opencode-session-send= or =opencode-session-command=, such as drover's and its scheduled ones. The input is sent once the service restored the session; the send checks run before, so input they keep restores nothing. Input sent meanwhile, from the buffer or elsewhere, waits for the same restore, and everything goes in the order it was sent; =RET= again while the input at the prompt waits only says so. Were the restore refused, nothing is sent: input typed at the prompt stays there, a notice in the buffer says why, and a caller of =opencode-session-send= gets the restore's error in its ELSE. Other sessions send as before, without a request more.

These functions also act on a session by its ID, with or without a buffer: =opencode-session-interrupt=, =opencode-session-last-reply=, =opencode-session-last-turn= (a recap of the last turn: its prompt, the agent's last reply since, the error it ended with, the files it changed with their added and deleted lines), =opencode-respond-session=, =opencode-rename-session= (ID and TITLE), =opencode-session-delete= (without confirmation; it kills the session's buffer), =opencode-session-fork= (the whole session, or what precedes a message ID; the fork is shown) and =opencode-session-compact=.

* Session buffers

Prompts are typed at the bottom. A prompt sent while a turn runs steers it (=opencode-prompt-delivery=); =opencode-queue-input= queues it for after the turn instead. Sent to an archived session, input brings the session back from the archive first (see [[*Session state][Session state]]). =/= at the start of the input picks a slash command, =!= runs a shell command, and =@= mentions a subagent. The keys:

| Key                           | Action                                                             |
|-------------------------------+--------------------------------------------------------------------|
| =RET=                         | send                                                               |
| =RET=, =mouse-2= on a prompt  | edit that earlier prompt again (=opencode-old-input-function=)     |
| =C-c RET= on a prompt         | put that earlier prompt in the input                               |
| =M-p=, =M-n=                  | previous or next input at the prompt, else previous or next button |
| =TAB= in the input            | complete at point, as in Shell mode                                |
| =TAB= elsewhere               | expand or collapse the block at point, else next button or block   |
| =<backtab>=                   | previous button, from the input too                                |
| =/= at the start of the input | pick a slash command                                               |
| =@= in the input              | mention a subagent                                                 |
| =C-c C-o=                     | open the link or file reference at point                           |
| =RET=, =TAB=, click           | on a block summary, expand or collapse it; on a link, follow it    |

Links in the transcript are Markdown and Org links, backticked file references such as =file.el:12=, and URLs written out (http, https, ftp, file), in the agent's text, its reasoning, tool output and code alike, and in the prompts sent, yours and other clients'; a URL ends before the punctuation closing its sentence, or a bracket it does not open. A URL becomes a link once it is complete, so one still streaming is not one yet. Text typed in the input is never a link: =RET= there sends it. In the transcript, =M-n= and =M-p= go from link to link, and =RET=, =mouse-1= and =C-c C-o= follow the one at point.

An earlier prompt, yours or another client's, is never sent again as it is. =RET= or =mouse-2= on it, but on a link of it, hands its whole text, every line, to =opencode-old-input-function=, which writes it where it is edited before being sent: nil, the default, puts it in the session's own input (=opencode-put-old-input=), replacing a blank input, or after a blank line following input typed already, which the echo area tells; drover sets it to put the prompt in its own prompt buffer, the session chosen as where it goes. =C-c RET= (=comint-copy-old-input=) always puts it in the input. Subagent mentions and files still on disk go with the prompt again, their labels standing for them as typed ones do; other attachments, such as a buffer, a region or an image sent inline, stay as the text of their labels. =RET= elsewhere in the transcript sends nothing.

Comint's other keys keep their meaning, such as =C-c C-n= and =C-c C-p= between prompts or =M-r= through the input history, and =comint-send-input=, from a key or =M-x=, sends as =RET= does, except those meant for a subprocess, since a session runs none: =C-c C-c= interrupts the turn (=opencode-interrupt=), =C-d= only deletes characters, never sending an end of file, and =C-c C-d=, =C-c C-z=, =C-c C-\=, =C-c M-o= and the Signals menu are refused, as is the In/Out menu's deletion of output: the transcript is the server's. =revert-buffer= (=opencode-session-reload=) renders the transcript again, keeping the input.

=TAB= in the input completes through =completion-at-point-functions=: Comint's history and file name completion first, then the global functions, such as a dabbrev function, for a word that names no file, then dictionary words, as in text modes when =text-mode-ispell-word-completion= is =completion-at-point=. In the read-only transcript it never completes.

Output follows the input as in any Comint buffer. A point at the end of the transcript or anywhere in the input, in every window showing the session, selected or not, stays after whatever is written there, at its place in the input: streamed answers, blocks expanding at the end, the prompt shown when a turn ends, notices, permission requests and questions, other clients' prompts. Redisplay then scrolls its window to keep it in view. A point elsewhere in the transcript stays at its text, and its window keeps its start. =revert-buffer= keeps them too: a point that followed output is back after the transcript rendered again, which may have grown meanwhile, and others at their line.

The other commands act on the current session:

|------------------------------------------------------------------------------+-----------------------------------------------------------------------------|

| =opencode-attach=                                                            | attach the region, else a file of the project or a buffer, offered together |
| =opencode-add-file=, =opencode-add-buffer-dwim=, =opencode-add-region=       | attach a file (a directory with a prefix argument), a buffer, the region    |
| =opencode-insert-slash-command=                                              | put a slash command at the start of the input                               |
| =opencode-mention-subagent=                                                  | mention a subagent                                                          |
| =opencode-select-agent=, =opencode-cycle-agent=                              | choose the agent (the other one when there are two), the next agent         |
| =opencode-select-model=, =opencode-select-variant=                           | choose the model, the variant                                               |
| =opencode-respond=                                                           | answer the pending permission request or question                           |
| =opencode-interrupt=                                                         | interrupt the turn                                                          |
| =opencode-fork-session=                                                      | fork the session at point                                                   |

The commands that edit the input (attaching, mentioning, slash commands) also work from other buffers, on the input of the last selected session buffer, and put what they insert at point when it is in the input, else at its end. =opencode-insert-slash-command= makes the text already typed the command's arguments, and replaces a command the input starts with.

=opencode-fork-session= and =opencode-revert-to-point= cut after the prompt or answer at point: in a prompt they keep it and drop its answer, in an answer they keep it and drop from the next prompt on. A prompt typed here becomes part of the conversation when the service delivers it, at once for an idle session, at the next step of a running turn when steering, after the turn when queued, and only from then on can a cut be made at it. A prompt typed while a turn streams stays where it was typed, and the cut follows the conversation's order rather than the buffer's. A slash command's input cuts as the prompt the service made of it; a shell command (=!=) makes no prompt, so a cut in it falls at the next prompt.

Images pasted with =yank-media= are attached to the next prompt. Attachments and mentions show as labels in the input; deleting a label drops its attachment. The input keeps them when another client's prompt is written before it and when the transcript is rendered again, by =revert-buffer= or after a reconnection.

=M-x cd= in a session buffer moves the session to the chosen directory. The buffer's directory follows the server: it changes when the move takes effect, and stays at the last confirmed location while a request is pending or if it fails. Moves made by the agent or another client are reflected automatically, including after reconnecting.

The mode line shows the session's status, title, agent, model, variant, provider and context use, fitted to the window. The status is the session's icon as every display of sessions shows it (see [[*Look][Look]]), followed by the icon of subagents waiting for you or working, at any depth, and by the archive's icon for an archived session; while a turn runs, the icon turns through the phases of the moon, a clock while it waits to retry, the same frame as drover's lists at the same time. Only the mode lines of the buffers a window of a visible frame shows animate, from one timer for all, which stops when none is left. A session that selected no variant shows, dimmed, the one its model runs with by default: =opencode-model-default-variant= finds the variant sending the reasoning effort that a request without one sends, from the provider and model catalogs, OpenCode's defaults for GPT-5 and the API's defaults for Claude (=opencode-anthropic-default-efforts=). =opencode-default-variant-function= can name another function, or none to show the provider's default as =default=. A model billed more past some context size, from its catalog pricing or =opencode-long-context-tiers=, is flagged as the context approaches it. After a compaction, the context use is the service's estimate of the next request, shown with a =~= until the next step measures it; with no estimate, from a native compaction or a service that does not give one, it is left out until then rather than show the size the compaction replaced. An estimate past a price tier is flagged but not reported, and the cache guard says when the context it may lose is an estimate. A mode line is fitted again only when what it shows, the window's width or the rest of the mode line changed, and a catalog arriving redraws only the shown mode lines of its location's sessions; =opencode-mode-line-flush= forgets the measured widths after a font change.

Each paragraph of the transcript has a tree-sitter parser of its own, which goes with its text. Earlier versions left parsers behind, which slowed every change of the buffer; a session buffer deletes them by itself, a little at a time, once it is first redrawn, and =opencode-session-prune-parsers= deletes them at once, in every session buffer with a prefix argument.

* Permissions and questions

A permission request marks the tool call that asked and waits; it never takes focus. =opencode-respond= opens it: accept once (=o=), always (=a=), reject and stop (=n=), reject with feedback (=f=), or hand the task off to another primary agent (=h=). Rejection with feedback blocks the tool but lets the assistant continue using the text you enter; plain rejection stops the current execution. Questions from the question tool open as a form, one question at a time, with your own answer always possible. Requests of a subagent run in the foreground show on the parent session's block. In a parent, =opencode-respond= answers its own request first, then the oldest of its subagents', at any depth, run in the foreground or in the background, switching to the subagent's buffer. An answer given in another client clears the request in Emacs.

A request can also be answered without leaving the buffer you are in, such as a session list: =(opencode-respond-session ID nil t)= opens the request's transient from the selected window and shows no session buffer. The transient then names the session first, and a permission to edit, patch or write a file shows the change asked for, cut to =opencode-request-preview-lines= lines; its menu shows at once even when transient menus are delayed, and the keys that scroll the transcript scroll it instead. A session with no request of its own answers its subagents' the same way, the oldest first. A session without a buffer, or whose buffer does not know the request yet, is loaded in the background first. The answer goes to the session asking, and its buffer, open or opened, shows the request answered. Without its third argument, =opencode-respond-session= shows the session's buffer and answers there.

While a request waits, the agent's step waits with it, and a prompt sent then is not an answer: the service delivers a steering prompt or command at the agent's next step, which comes only once the request is answered or dismissed. A subagent run in the foreground holds up its parent the same way, as the parent's step waits for the subagent's turn to end; one run in the background does not, and a prompt to its parent is read as usual. So =RET= asks first when the session, or a subagent it runs in the foreground, at any depth, waits on a request, saying which: answer it (=opencode-respond=, keeping the input), send anyway (the prompt waits for the request to be settled), or cancel (keeping the input). Queued input (=opencode-queue-input=) waits for the end of the turn anyway, and a shell command runs at once, so neither asks; neither do sends that run no check, such as scheduled ones through =opencode-session-send=, which wait the same way.

* Edits

After each edit, write or patch tool call of a live turn, =opencode-file-edited-functions= run with the file and the line ranges the edit left. By default, Lisp files with unbalanced parentheses are fixed with parinfer when installed, Node projects with a local Prettier configuration are formatted by that Prettier, and other files are reindented where the edit touched them. Org files are only reindented by =opencode-org-indent-function=. When the turn ends, =opencode-files-finished-editing-functions= run with every file it edited; by default Flycheck checks them and its errors and warnings are sent back to the agent. Files with unsaved Emacs edits are never touched, and nothing ever asks whether to reread a file. Processing runs in the background, so it never asks anything at all: a file visited for it gets only its safe local variables, those of a =.dir-locals.el= included, and is left alone rather than ask whether to apply risky ones; a mode hook or anything else that would ask fails instead (=opencode-without-asking=). A transcript written whole, when a session opens or catches up after a reconnection, processes none of the files its turns edited.

* Prompt cache and thinking

With my fork, before an idle session sends a turn, the service reports how much of the cached prompt it would re-send uncached and why; above =opencode-cache-guard-threshold= tokens, Emacs asks first. When earlier thinking no longer matches the conversation, other clients let the provider drop it unseen; Emacs has the service refuse such turns and asks whether to replace that thinking with its text. Declining keeps the input in the prompt.

* Notifications

A turn that ends, a retry, and a permission request or question of a session that is not displayed are logged in the hidden buffer =*OpenCode Notifications*=. =opencode-notification-messages-filter= and =opencode-notification-os-filter= decide what also reaches =*Messages*= and the operating system, through =opencode-notify-os-function=: D-Bus, macOS notifications, Windows tray notifications, or =opencode-notify-os-alert= for the alert package.

Backends that support removal return a dismissal function. Answering or declining a request removes its own notification, including answers from another client. Sending a new prompt or command clears the previous turn's notifications; killing the session buffer clears all of its notifications. The hidden notification log is retained. Custom backends can use =opencode-notification-id= for a stable session/kind/request key and return a zero-argument function to remove that toast.

* Desktop

Session buffers are saved with the desktop by session ID, directory and point, and restored in place in the background. A point that followed output comes back at the end of the transcript, which may have grown since, and windows that showed the buffer while it was restored follow its output as any other. A restore that fails, because the service is unavailable or the session was deleted, leaves a placeholder that is still saved; =g= in it retries. The restore's =opencode-desktop-restore-timeout= counts from the moment the service is ready, so a slow start or import does not use it up.
