#+TITLE: opencode.el
#+OPTIONS: toc:nil

An Emacs client for [[https://opencode.ai/][OpenCode]] 2, the open source coding agent. Each session is a Comint buffer with Markdown rendering, collapsible reasoning and tool blocks, and permission requests and questions that wait for you without taking focus. It connects to the shared background service the OpenCode TUI and desktop app use, starting it when needed, and never stops it.

This package started as [[https://codeberg.org/sczi/opencode.el][sczi's opencode.el]] for OpenCode 1. It was rewritten for OpenCode 2's API and event model, keeping its Comint foundation, its session tables and its post-edit hooks.

* Requirements

- Emacs 31.1 with the =markdown= and =markdown-inline= tree-sitter grammars (=M-x markdown-ts-mode-install-parsers=, or set =opencode-ensure-grammar-function=).
- [[https://github.com/alphapapa/plz.el][plz]] and [[https://github.com/magit/transient][transient]], and =curl= on the =PATH=.
- OpenCode 2. The prompt-cache guard and stale-thinking consent need routes only [[https://github.com/vleonbonnet/opencode][my fork]] has; with stock OpenCode the guard switches itself off.

* Installation

With elpaca or straight:

#+begin_src emacs-lisp
(use-package opencode
  :ensure (:host github :repo "vleonbonnet/opencode.el"))
#+end_src

With =package-vc=:

#+begin_src emacs-lisp
(use-package opencode
  :vc (:url "https://github.com/vleonbonnet/opencode.el" :rev :newest))
#+end_src

* The service

OpenCode 2 runs one background service per user. It registers its URL, process ID, version and password in =~/.local/state/opencode/service.json= (=$XDG_STATE_HOME/opencode/service.json= when set). Emacs reads that file, checks that the registered process answers, and runs =opencode service start= when none does. A restarted service is found again from the file, and running turns resume. =M-x opencode-service-restart= restarts it, for instance after installing a new build; =opencode-service-stale-functions= run when the service is older than the installed CLI. =M-x opencode-service-stop= stops it and closes Emacs's event stream, so nothing starts it again until a session is reopened.

On its first start, the service imports the sessions of OpenCode 1 in the background while it already answers, and a session it has yet to import looks deleted. Emacs therefore waits for the import before sending anything, showing its progress in the echo area; an import that fails, or makes no progress for =opencode-service-import-stall-timeout= seconds, is reported as a warning and no longer waited for.

* Sessions

=M-x opencode= lists the sessions of the current project, including those of its worktrees, with their branch. =M-x opencode-list-all-sessions= lists every project's. Archived sessions are left out, and subagent sessions are hidden until =opencode-session-list-toggle-subagents= shows them. An icon of each session's status (see [[*Session state][Session state]]) leads its title, names the status in its tooltip, and changes with it: =nf-md-help_circle= waiting for you, =nf-md-timer_sand= working, =nf-fa-refresh= retrying, =nf-fa-times_circle= failed and =nf-md-check_circle= done while unseen, =nf-fa-circle_o= idle. These are [[https://www.nerdfonts.com][Nerd Font]] icons, so a Nerd Font must be installed for them to show; =opencode-session-status-icons= sets the icon and face of each. The Title column sorts by title, whatever the icons. Titles of sessions open in a buffer use =opencode-session-list-open-session= (inheriting =success=), even when the buffer is hidden; the highlight follows buffers opening and closing.

A list binds only standard keys: =RET= opens the session at point, =g= (=revert-buffer=) fetches the list again, and the keys of =special-mode= and vtable apply (=q= quits, =S= sorts by the column at point, ={= and =}= narrow and widen it). =opencode-session-list-id-at-point= returns the session on the row at point, for commands of other packages. =opencode-rename-session=, =opencode-archive-session=, =opencode-delete-session= and =opencode-interrupt= act on the row at point in a list, as they act on the buffer's session in a session buffer.

Other entry points: =opencode-select-project=, =opencode-select-session=, =opencode-new-session=, =opencode-session-list-new= (a session in the list's directory), =opencode-new-worktree= (a new branch in a worktree under =opencode-worktree-directory=, with a session in it), =opencode-select-open-session=, =opencode-consult-sessions=, =opencode-toggle-mcp= (connect or disconnect an MCP server), and =opencode-visit-last-idle= or =opencode-select-idle= for sessions that finished or started waiting while not displayed.

opencode.el binds only the keys every Comint, special-mode or vtable user expects, and leaves its other commands unbound. [[https://github.com/vleonbonnet/drover][drover]] provides key maps for them: one-key session actions in session lists, and a transient (=drover-dispatch=) holding those, the prompt's commands and global ones. Without drover, call the commands with =M-x= or bind them yourself.

* Session state

Emacs keeps the live state of the recent sessions and of every running one, whether or not they have a buffer, in the registry =opencode-state=: whether a turn runs, the retry it waits for, the permission requests and questions waiting on you, and how the last turn ended. It follows the service's events, and rebuilds itself from the service every time the event stream connects, whoever opened it; =opencode-state-ensure= opens the stream for it. =opencode-state-recent-limit= sets how many recent unarchived sessions it loads.

A session's status, from =opencode-state-status=, is =waiting= while a request awaits you, =retrying= or =working= while a turn runs, =failed= or =done= when a turn ended that nobody viewed yet, and =idle= otherwise. =opencode-state-change-functions= run when a status changes and =opencode-state-updated-functions= when anything about a session does, for session lists, dashboards and mode lines.

Whether a finished turn was seen is the service's read marker, shared by every client. Showing a session's buffer in the selected window of a focused frame, or a turn ending while it is shown there, marks the session viewed (=opencode-session-view=), for the TUI and the desktop app too; a session viewed in another client is no longer done in Emacs either.

Archiving a session (=opencode-session-archive=) hides it from the lists and from =opencode-state-sessions= without deleting it; =opencode-session-archive= with a non-nil RESTORE argument brings it back. These functions also act on a session by its ID, with or without a buffer: =opencode-session-interrupt=, =opencode-session-last-reply=, =opencode-respond-session=, =opencode-rename-session= (ID and TITLE), =opencode-session-delete= (without confirmation; it kills the session's buffer), =opencode-session-fork= (the whole session, or what precedes a message ID; the fork is shown) and =opencode-session-compact=.

* Session buffers

Prompts are typed at the bottom. A prompt sent while a turn runs steers it (=opencode-prompt-delivery=); =opencode-queue-input= queues it for after the turn instead. =/= at the start of the input picks a slash command, =!= runs a shell command, and =@= mentions a subagent. The keys:

| Key                           | Action                                                             |
|-------------------------------+--------------------------------------------------------------------|
| =RET=                         | send                                                               |
| =M-p=, =M-n=                  | previous or next input at the prompt, else previous or next button |
| =TAB=                         | expand or collapse the block at point, else next button            |
| =<backtab>=                   | previous button                                                    |
| =/= at the start of the input | pick a slash command                                               |
| =@= in the input              | mention a subagent                                                 |
| =C-c C-o=                     | open the link or file reference at point                           |
| =RET=, =TAB=, click           | on a block summary, expand or collapse it; on a link, follow it    |

Comint's other keys keep their meaning, such as =C-c C-n= and =C-c C-p= between prompts or =M-r= through the input history, except those meant for a subprocess, since a session runs none: =C-c C-c= interrupts the turn (=opencode-interrupt=), =C-d= only deletes characters, never sending an end of file, and =C-c C-d=, =C-c C-z=, =C-c C-\=, =C-c M-o= and the Signals menu are refused, as is the In/Out menu's deletion of output: the transcript is the server's. =revert-buffer= (=opencode-session-reload=) renders the transcript again, keeping the input.

The other commands act on the current session:

| Command                                                                      | Action                                                                      |
|------------------------------------------------------------------------------+-----------------------------------------------------------------------------|
| =opencode-queue-input=                                                       | send after the running turn                                                 |
| =opencode-attach=                                                            | attach the region, else a file of the project or a buffer, offered together |
| =opencode-add-file=, =opencode-add-buffer-dwim=, =opencode-add-region=       | attach a file (a directory with a prefix argument), a buffer, the region    |
| =opencode-insert-slash-command=                                              | put a slash command at the start of the input                               |
| =opencode-mention-subagent=                                                  | mention a subagent                                                          |
| =opencode-select-agent=, =opencode-cycle-agent=                              | choose the agent (the other one when there are two), the next agent         |
| =opencode-select-model=, =opencode-select-variant=                           | choose the model, the variant                                               |
| =opencode-respond=                                                           | answer the pending permission request or question                           |
| =opencode-interrupt=                                                         | interrupt the turn                                                          |
| =opencode-fork-session=                                                      | fork the session at point                                                   |
| =opencode-revert-to-point=, =opencode-revert-clear=                          | stage a revert after point, cancel it                                       |
| =opencode-compact-session=                                                   | compact the conversation                                                    |
| =opencode-select-child-session=, =opencode-open-parent=                      | open a subagent session, the parent session                                 |
| =opencode-yank-code-block=, =opencode-copy-conversation=                     | copy the code block at point, the whole conversation as Markdown            |
| =opencode-scroll-to-last-response-start=                                     | go to the start of the last answer                                          |
| =opencode-rename-session=, =opencode-archive-session=, =opencode-delete-session=, =opencode-new-session= | rename, archive, delete, new session                         |

The commands that edit the input (attaching, mentioning, slash commands) also work from other buffers, on the input of the last selected session buffer, and put what they insert at point when it is in the input, else at its end. =opencode-insert-slash-command= makes the text already typed the command's arguments, and replaces a command the input starts with.

Images pasted with =yank-media= are attached to the next prompt.

=M-x cd= in a session buffer moves the session to the chosen directory. The buffer's directory follows the server: it changes when the move takes effect, and stays at the last confirmed location while a request is pending or if it fails. Moves made by the agent or another client are reflected automatically, including after reconnecting.

The mode line shows the session's status, title, agent, model, variant, provider and context use, fitted to the window. A model billed more past some context size, from its catalog pricing or =opencode-long-context-tiers=, is flagged as the context approaches it.

* Permissions and questions

A permission request marks the tool call that asked and waits; it never takes focus. =opencode-respond= opens it: accept once (=o=), always (=a=), reject and stop (=n=), reject with feedback (=f=), or hand the task off to another primary agent (=h=). Rejection with feedback blocks the tool but lets the assistant continue using the text you enter; plain rejection stops the current execution. Questions from the question tool open as a form, one question at a time, with your own answer always possible. Requests of a subagent show on the parent session's block. An answer given in another client clears the request in Emacs.

* Edits

After each edit, write or patch tool call of a live turn, =opencode-file-edited-functions= run with the file and the line ranges the edit left. By default, Lisp files with unbalanced parentheses are fixed with parinfer when installed, Node projects with a local Prettier configuration are formatted by that Prettier, and other files are reindented where the edit touched them. Org files are only reindented by =opencode-org-indent-function=. When the turn ends, =opencode-files-finished-editing-functions= run with every file it edited; by default Flycheck checks them and its errors and warnings are sent back to the agent. Files with unsaved Emacs edits are never touched, and nothing ever asks whether to reread a file.

* Prompt cache and thinking

With my fork, before an idle session sends a turn, the service reports how much of the cached prompt it would re-send uncached and why; above =opencode-cache-guard-threshold= tokens, Emacs asks first. When earlier thinking no longer matches the conversation, other clients let the provider drop it unseen; Emacs has the service refuse such turns and asks whether to replace that thinking with its text. Declining keeps the input in the prompt.

* Notifications

A turn that ends, a retry, and a permission request or question of a session that is not displayed are logged in the hidden buffer =*OpenCode Notifications*=. =opencode-notification-messages-filter= and =opencode-notification-os-filter= decide what also reaches =*Messages*= and the operating system, through =opencode-notify-os-function=: D-Bus, macOS notifications, Windows tray notifications, or =opencode-notify-os-alert= for the alert package.

Backends that support removal return a dismissal function. Answering or declining a request removes its own notification, including answers from another client. Sending a new prompt or command clears the previous turn's notifications; killing the session buffer clears all of its notifications. The hidden notification log is retained. Custom backends can use =opencode-notification-id= for a stable session/kind/request key and return a zero-argument function to remove that toast.

* Desktop

Session buffers are saved with the desktop by session ID, directory and point, and restored in place in the background. A restore that fails, because the service is unavailable or the session was deleted, leaves a placeholder that is still saved; =g= in it retries. The restore's =opencode-desktop-restore-timeout= counts from the moment the service is ready, so a slow start or import does not use it up.

* Development

| Command         | Runs                                                            |
|-----------------+-----------------------------------------------------------------|
| =make test=     | every ERT test in a batch =emacs -Q=                            |
| =make test-gui= | the tests that need a graphical frame, in a separate =emacs -Q= |
| =make compile=  | byte compilation with warnings as errors                        |
| =make lint=     | checkdoc                                                        |

=DEPS= names the directory holding the dependencies, one subdirectory each, elpaca's builds directory by default. Tests replay events and messages recorded from a real service (=test/fixtures/v2=) and talk HTTP to a local fake service; they never touch a running Emacs session or OpenCode service.
